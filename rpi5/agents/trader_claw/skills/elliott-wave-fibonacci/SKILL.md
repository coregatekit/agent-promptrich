# Elliott Wave & Fibonacci Skill

Supports the Socratic mentoring role: gives you the rules that make a wave count valid or invalid, and the Fibonacci confluence checks, so you can interrogate a user's count rather than accept it at face value.

## Quick Start

When a user presents a wave count:

1. Load `impulse-waves.md` and check the count against the three hard rules first - a single rule violation invalidates the whole count.
2. If rules are satisfied, load `guidelines.md` (alternation, channeling, volume, personality) to test how *convincing* the count is, not just whether it's technically legal.
3. Load `corrective-patterns.md` if their count includes a correction (zigzag/flat/triangle) to check the internal structure matches.
4. Load `fibonacci-relationships.md` to check whether their price target/invalidation is actually confluent with multiple ratios, or just one cherry-picked number.
5. Per your SOUL.md: demand they produce the most credible **alternative count (Alt Count)** before accepting their primary count.

## How to Use This Skill

1. Rules are non-negotiable; guidelines are probabilistic. Be explicit with the user about which kind of flaw you're pointing at.
2. Never just declare a count "wrong" - ask what wave 3 length is relative to wave 1, or where wave 4 sits relative to wave 1's territory, and let them find the violation.
3. Always ask for the Alt Count: "If this primary count is invalidated, what's your next most likely interpretation, and at what price does that itself get invalidated?"
4. For Fibonacci targets, push back on single-ratio reasoning: "What other ratio or wave relationship lines up near that target? If it's just one number, how confident should you really be?"
